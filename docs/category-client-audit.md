## Источники и формат доказательств

`data/category-client-research.json` содержит полный снимок112групп фильтров: точное название, facetId/alias, варианты, значения, ссылки и `clientCount` из атрибута `data-drupal-facet-item-count`. Для каждого варианта сохранён HTML ссылки; для страницы — SHA256, URL и селектор. Исходные HTML находятся в TEMP и не добавлены в приложение.

Группы читаются из `.filters__block`, названия — `.filters__field-title`, варианты — `a[data-drupal-facet-item-value]`, подпись — `.facet-item__value`. Диапазоны цены берутся из публичного `drupalSettings.facets.sliders`, не вычисляются по первому экрану карточек.

## Конфликты, исключённые из нормализованных фасетов

- **RF65DB970012WR:** название обещает551л, строка «Общий объем, л» —676. `volumeLiters` не назначен. Цвет корпуса/палитры — чёрный, цвет дверцы — белое стекло; смешивать их нельзя.
- **VS15A6031R5EV:** таблица помечает и сухую/влажную уборку, и оба места управления значением «Нет». Эти четыре сомнительных поля оставлены только в rawSpecs.
- **SM-R540NZWACIS:** «Тип: вкладыши», но одновременно «Вставные: Да» и «Внутриканальные: Да». `headphoneType` и общий `type` исключены из normalized.

Для Ultra менять RAM/ROM/цвет по точному SKU: у256/512ГБ —12ГБ RAM; у1ТБ —16ГБ RAM, как уже подтверждено в product-sources.json. Остальные общие характеристики ранее сравнивались между12карточками.

## Правила реализации демо

1. `clientCount` относится ко всему магазину клиента. В демо показывать результаты пересчёта только своих35/45SKU и текущих выбранных фильтров.
2. Внутри одной группы использовать OR, между группами AND; сброс очищает все значения. Поддержать понятное пустое состояние.
3. Не показывать пустые фасеты и сомнительные поля. Неизвестный параметр не должен совпадать ни с «Да», ни с «Нет».
4. Локальные дополнения (ROM планшетов, размер корпуса часов, мощность всасывания) основаны на карточках, но не выдаются за существующие фасеты клиента.
5. Наличие не доказано отдельно для всехSKU: не определять его по цене, наличию кнопки или отсутствию товара на первой странице каталога.
6. Для холодильника в локальном каталоге один товар, для наушников/аксессуаров/планшетов/пылесосов — по два. Один постоянный вариант фильтра не создаёт полезного выбора; такие группы лучше скрыть.

## Итоговая реализация

Первичный снимок выше охватывает 35 исходных SKU. После расширения используются 60 проверенных конфигураций / 44 модели: 15 дополнительных SKU из `data/category-extra-products.json` и десять дополнительных конфигураций Ultra из существующего `product-sources.json`. На странице смартфонов — 13 моделей / 26 конфигураций. Числа в интерфейсе пересчитаны по текущей подборке, без переноса общего количества магазина.

Отдельно проверено наличие точного SKU в основной области PDP: `data/category-availability.json`. Из 60 конфигураций 57 имеют явную метку наличия, одна — «Нет в наличии», две — только «Только онлайн», что оставлено неопределённым. Статус не выводится из цены или кнопки. «Есть в N магазинах» означает наличие в магазинах, без обещания доставки. Условия на действующем сайте могут измениться.

Дополнительные источники добавили конфликт объёма RS70 и форм-фактора Buds Core. Спорные значения исключены из фильтров и сравнения. Для холодильников цвет соответствует отдельному доказанному полю дверцы, поскольку цвет корпуса и фасада может отличаться.

Фотографии официальные, полные исходные полотна в WebP. Оригинальные пропорции и границы предметов сохранены; новые рисунки устройств не генерировались. Компоновка адаптирована по предоставленному референсу, палитра и шрифты взяты из существующего дизайна.
